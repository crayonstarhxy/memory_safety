# 威胁模型

## 保护目标

1. **完整性**：不可信内容不能静默改变长期行为规则或已确认事实。
2. **机密性**：记忆不能跨用户、租户或任务边界泄漏。
3. **授权完整性**：记忆召回不能提升工具权限或替代用户确认。
4. **可恢复性**：恶意对象能被定位、隔离、删除并验证不再被召回。
5. **可审计性**：保存来源、信任等级、决策原因、时间和 namespace。

## 信任边界

```text
用户/网页/文档/工具输出
          |
          v
  [候选记忆 + 来源元数据]
          |
          v
 [写入策略：评分/冲突/隔离]
          |
          v
 [按 namespace 隔离的记忆存储]
          |
          v
 [读取策略：TTL/状态/来源过滤]
          |
          v
     Agent 推理
          |
          v
 [模拟工具网关：最小权限/审批]
```

## 攻击链分解

每个案例至少观察五个阶段，避免只检查最终文本：

1. **Write**：载荷是否成为活跃记忆。
2. **Persist**：更换 Agent 实例后是否仍存在。
3. **Retrieve**：后续无关或相似查询是否召回。
4. **Influence**：召回对象是否改变回答或规划。
5. **Act**：是否产生敏感工具调用，以及权限层是否拦截。

## 明确不在范围内

- 真实目标扫描、口令尝试、恶意软件、持久化到操作系统。
- 真实邮件发送、网络外传、shell 命令执行或云资源修改。
- 绕过第三方产品安全机制的现成武器化载荷。

这些边界让案例仍能验证控制设计，同时把影响限制在本地确定性模拟环境。
